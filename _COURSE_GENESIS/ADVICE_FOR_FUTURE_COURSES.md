# Strategic Advice for "Fundamentals of Web Programming"
**Target Era:** 16-Week Format | 8-Week Agile Project

## 1. The "Dual-Track" Pedagogical Model
- **Lesson learned from Python:** Keep the Academic (A-Side) and Applied (B-Side) decoupled but synchronized. 
- **Web Advice:** Week 1-8 should be "The Toolset" (HTML, CSS, JS Basics). Week 9-16 should be "The System" (Frameworks, State, Agile Sprints).
- **The Gap:** Students struggle to bridge syntax to systems. Use the **Sprint Bridge** checklists at the end of every Week 1-8 lab to force them to hypothesize how a `<div>` or a `fetch()` call will be used in their final project.

## 2. Elite Effectiveness Components
- **Interactive Knowledge Checks (IKC):** In Web Programming, these are CRITICAL. Embed "Try it in the Console" prompts and "Reveal Answer" buttons for CSS specificity and JS closure questions. 
- **Software Developer Pro-Tips (SDP):** Focus on "Clean Code" for CSS (BEM naming) and "Performance" for JS (de-bouncing, async/await). Link every lesson to MDN Documentation—teach them to read the professional spec.

## 3. Responsible AI (The Jeanie Protocol)
- Do not let students use AI blindly for CSS layouts. It will hallucinate flexbox vs grid solutions.
- **Advice:** Gated AI must be the tutor. Upload MDN-standard lessons to NotebookLM. Only allow Jeanie to suggest patterns, never to write the full `.html` file.

## 4. Quality Matters (QM) by Design
- Start with Accessibility (Standard 8.2). Intro to Web is the perfect place to teach ARIA labels and semantic HTML from Day 1.
- Standard 7 (Support): Include the MCC Learner Support template as a mandatory "Module 0" page.

## 5. The "Sprint 0" Pivot
- In Python, we found that students need a "Mandatory Milestone" check. 
- **Web Advice:** Week 9 must be a complete "UI Mockup" review before any JS logic is written. This prevents students from biting off more than they can chew with complex APIs.
