Overview

Professional developers don't just "save" files. We build histories. Git is a time machine. It allows you to save "checkpoints" of your code so you can always go back if you break something.

Today you will set up your GitHub account and build a content pipeline to your live server.

♿ Accessibility Note: GitHub's interface now supports dark mode and high-contrast themes, making it more accessible for users with visual impairments.

👀 Look & Learn: The Data Pipeline

This is how your code travels from your brain to the world.

YOU (Local) 
⬇ (Push)
GitHub (The Cloud) 
⬇ (Pull/Clone)
The Internet (Live Site)
The Logic:
  • Repo: A folder that is tracked by Git.
  • Commit: A "Save Point" in history.
  • Push: Uploading your commits to the cloud.

💻 Project: The Time Capsule

You will create a repository and prove you can update it live.

Phase 1: The Launch

  1. Create a Public GitHub repo named ADD103.
  2. Connect it to cPanel (as detailed in the course videos).
  3. Upload your manifesto.html from Lesson 1A.
  4. Verify it appears on your live student URL (e.g., yourname.mccstudent.com/ADD103/week_01/manifesto.html).

Phase 2: The Update (Breaking the Seal)

A website is never finished. We need to change it.

  1. Back on your computer, open `manifesto.html`.
  2. Add a new line at the bottom: "Timestamp: I have successfully deployed this site on [Date]!"
  3. Save, Commit, and Push the change to GitHub.
  4. Go to your live URL. Refresh the page.

Did the new text appear? If so, you have mastered the infinite loop of web development.
